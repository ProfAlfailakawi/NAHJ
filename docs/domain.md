# ربط نطاقك بنهج

خطواتٌ لمرة واحدة. تحتاج: نطاقاً مشترى (مثل `nahj.com.kw` أو `your-brand.com`)،
ودخولاً إلى لوحة DNS عند مسجّل النطاق، وأن يكون النشر التلقائي مُعدّاً
(`docs/deploy-nahj.md`) — أي أن الخادم قائم وله عنوان ثابت.

---

## ١. اختر الاسم

| الخيار | مثال | متى |
|---|---|---|
| النطاق نفسه | `nahj.com.kw` | الموقع كله نهج — الأبسط |
| نطاقٌ فرعي | `app.your-company.com` | لموقعك الرئيسي استضافةٌ أخرى |

ولكل عميل لاحقاً نطاقٌ فرعي عنده أو عندك (`shifa.nahj.com.kw`) — انظر «خوادم
العملاء» في `docs/deploy-nahj.md`.

## ٢. اعرف عنوان الخادم الثابت

من Cloud Shell:

```bash
gcloud compute addresses list --filter="name=nahj-ip"
```

العنوان في عمود `ADDRESS` (مثل `34.140.12.7`). وهو محجوز: لا يتغيّر مع إعادة
التشغيل، فلا ينكسر النطاق.

## ٣. سجلّ DNS عند مسجّل النطاق

أضف سجلاً واحداً:

| النوع | الاسم | القيمة | TTL |
|---|---|---|---|
| `A` | `@` للنطاق نفسه، أو `app` للفرعي | عنوان الخادم من الخطوة ٢ | 300 |

وتحقّق أنه انتشر (دقائق عادةً، وقد يصل إلى ساعات):

```bash
dig +short nahj.com.kw     # يجب أن يطبع عنوان الخادم
```

> **لا تنتقل إلى الخطوة التالية قبل أن يطبع العنوان الصحيح.** Let's Encrypt
> تتحقق من النطاق عبره، ومحاولاتٌ متكرّرة على نطاقٍ لم ينتشر تُوقَف مؤقتاً.

## ٤. أخبر النشر بالنطاق

GitHub ← Settings ← Secrets and variables ← Actions ← **Variables**:

| المتغيّر | القيمة |
|---|---|
| `NAHJ_DOMAIN` | `nahj.com.kw` (بلا `https://` وبلا `/`) |

ثم شغّل الورك-فلو يدوياً: تبويب **Actions** ← «نشر نهج» ← **Run workflow**.

ما يحدث: Caddy على الخادم يطلب شهادة Let's Encrypt للنطاق ويجدّدها تلقائياً،
وكل طلب `http` يُحوَّل إلى `https`، و`NAHJ_PUBLIC_URL` يصير `https://nahj.com.kw`
تلقائياً — وهو ما تشتقّ منه بوابة الدفع عنوان الإشعار وعنوان العودة.

والسجلّ لا يُعلن النجاح حتى يردّ الخادم فعلاً على `https://<نطاقك>`.

## ٥. بعد الربط مباشرةً

1. افتح `https://<نطاقك>` — الصفحة الرئيسية بنموذج «اطلب عرضاً».
2. افتح `https://<نطاقك>/app` وادخل بحساب المالك.
3. اضبط بيانات التواصل على الخادم:
   ```bash
   bash scripts/server-env.sh set NAHJ_CONTACT_EMAIL=sales@<نطاقك> NAHJ_LEGAL_NAME="..."
   ```
4. **بوابة الدفع**: عنوان الإشعار عند المزوّد هو
   `https://<نطاقك>/api/payments/webhook/<المزوّد>` — الخطوات في `PAYMENTS.md`.
5. `bash scripts/server-env.sh check` — يجب أن يخرج بلا موانع.

## ٦. البريد من نطاقك (اختياري، موصى به)

لتصل رسائل نهج (طلبات العرض، الفواتير، تذكير التجديد) من `noreply@<نطاقك>` لا إلى
مجلد الرسائل المزعجة: في لوحة مزوّد البريد (Resend أو SendGrid) أضف نطاقك، وانسخ
سجلات DNS التي يعطيك إياها (عادةً `TXT` لـ SPF و`CNAME` أو `TXT` لـ DKIM) إلى لوحة
DNS نفسها، ثم:

```bash
bash scripts/server-env.sh set NAHJ_MAIL_PROVIDER=resend NAHJ_MAIL_API_KEY=<المفتاح> NAHJ_MAIL_FROM=noreply@<نطاقك>
```

## إن لم يعمل

```bash
gcloud compute ssh nahj --zone europe-west1-b --command 'docker logs caddy 2>&1 | tail -30'
```

| ما تراه | السبب | العلاج |
|---|---|---|
| `NXDOMAIN` أو عنوانٌ آخر | DNS لم ينتشر أو السجلّ خاطئ | راجع الخطوة ٣ وانتظر |
| `too many failed authorizations` | محاولات كثيرة قبل الانتشار | انتظر ساعة ثم أعد التشغيل |
| الموقع يعمل على العنوان القديم فقط | `NAHJ_DOMAIN` لم يُضبط أو لم يُعَد النشر | الخطوة ٤ |
